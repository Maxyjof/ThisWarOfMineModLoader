## LuaModdingAPI规则注册层

- 增加独立`api_version`字段`1.0.0`，不改变旧加载器版本字段和`TWOMLoader`兼容别名
- 增加数值、布尔和字符串规则；数值可限范围，字符串可限枚举和最大长度
- 规则由提供模组命名空间拥有，只有自身或清单明确声明的直接依赖可读写；修改通知携带新值、旧值和规则ID
- 模组入口失败时撤销自有规则；该入口对依赖规则的值改动回滚，并通知仍有效的监听者
- 内置MCP增加只读`rule_list`，运行时快照按规则ID排序
- `examples/rule-api`含提供方与依赖调整器，演示跨模组读取、改值、通知和兼容元数据
- Lua5.1测试覆盖默认值、三种数据类型、数值范围、字符串选项、依赖权限、失败入口回滚、变更通知及快照顺序；模组计划通过CLI检查

规则注册本身不会更改游戏玩法；需要针对特定游戏回调制作适配模组。规则值只在进程生命周期内有效，没有游戏内编辑器或跨启动保存，也没有验证原生剧情事件或世界对象API。该阶段验证的是加载器的运行时规则契约，不是任何真实游戏数值改动

## 显式授权的模组MCP工具

- 模组清单新增能力白名单，目前只接受`mcp.tools`；LuaBundle把能力传给入口上下文，未声明的模组注册工具会失败
- 模组可定义最多32个扁平字符串、有限数值、整数或布尔参数，以及必填字段和只读/破坏性提示；工具发现时动态加入MCP工具列表
- MCP服务从游戏Lua主线程读取已注册动作，通过固定CLI服务再校验参数类型、必填项和未知字段；参数按UTF8十六进制分字段传输，Lua端不解析或编译客户端代码
- `examples/mcp-tools`提供回声工具，Lua5.1运行时测试覆盖未授权拒绝、注册失败撤销、调用类型和必填校验；MCP协议测试通过真实服务进程和文件桥替身验证动态发现、Unicode参数和错误隔离
- Release构建零警告零错误，41项C#测试及五个Python验证入口通过

目前MCP扩展工具协议仅由测试文件端验证，没有在真实游戏会话中注册并调用示例工具；`mcp.tools`是可信模组权限，不能视为Lua沙箱或安全边界。游戏动作是否按预期影响玩法仍须逐个实机验证
